작성일: 2026-06-01 | 최종 실험: 20260526_172609_lgbcat_timesplit

핵심 결론

성능 개선 두 번 발생. 첫 번째는 실제 앱명 기반 daily/evening app feature를 추가했을 때이고, 두 번째는 취침 전·야간·새벽 시간대 app context feature를 추가했을 때이다. 최종 LB logloss는 0.6218831823에서 0.6106185586으로 개선.




1. 목적

본 보고서는 수면 관련 예측 지표(Q1-Q3, S1-S4)의 성능 향상을 위해 어떤 feature를 추가했을 때 leaderboard 성능이 개선되었는지 정리한 문서이다. 과제의 초점은 feature engineering을 통해 성능 향상에 기여한 변수를 확인하는 것이다.

3. 기준 모델: 수면/생체/행동 Feature

기준 모델은 앱 context feature를 추가하기 전, 수면과 생체신호 중심으로 구성된 feature set을 사용했다. 수면 시작/종료를 직접 관측할 수 없기 때문에 screen off, HR 안정화, light 감소 등을 이용해 수면 구간을 추정했다.

4. 1차 개선: 앱명 기반 Daily / Evening Feature

1차 개선에서는 mUsageStats raw 데이터에 포함된 실제 앱 이름을 이용해 앱 사용 feature를 추가했다. 기존에는 앱 사용량을 social, video, game, browser 등 대략적인 카테고리로만 사용했지만, 이 단계에서는 실제 앱명을 의미 있는 앱군으로 묶었다.

5. 2차 개선: Presleep / Night / Early-Morning App Context

2차 개선에서는 앱 사용을 단순 daily total로 보지 않고, 수면과 직접 연결되는 시간 구간별로 나누었다. 이 단계가 가장 큰 성능 개선을 만들었다.

5.1 생성한 app context feature

기본 사용량: usage_total_min, usage_n_apps, usage_entropy, usage_top_app_ratio, app_switch_count

앱 카테고리: social_min, video_min, game_min, browser_min, shopping_min, other_min

7. 결론

첫 번째 개선은 실제 앱명을 활용한 daily/evening app feature를 추가했을 때 발생했다.

두 번째 개선은 앱 사용을 취침 전, 야간, 새벽 시간대로 나누는 app context feature를 추가했을 때 발생했다.

수면 예측에서는 하루 전체 앱 사용량보다 수면과 가까운 시간대의 앱 사용 맥락이 더 강한 신호였다.



보고서용 요약 문장

본 실험에서는 앱 사용 feature를 단계적으로 확장하였다. 앱명 기반 daily/evening feature 추가 후 logloss는 0.6219에서 0.6183으로 개선되었고, 취침 전 2시간, 취침 전 4시간, 밤 22-02시, 수면 예상 시간 00-06시, 새벽 04-08시로 세분화한 app context feature를 추가한 뒤 최종 logloss는 0.6106까지 개선되었다. SHAP 분석 결과 presleep 및 sleep-window app usage, communication app ratio, app switch count, stimulating app usage가 여러 target에서 중요 feature로 나타났다.
